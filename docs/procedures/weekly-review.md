# Weekly review

> [!QUESTION] Goal: how is a week closed and the next one committed, in 45 minutes?

1. **Inbox.** Process the inbox: attach each item to a parent, send it to the holding file or to the ideas file, or discard it. A request of the class `scheduled` is processed here.
2. **Metrics.** Read the [metrics](../kernel/processes/feedback.md#^core-metrics), and the metric of each option turned on.
3. **Findings.** Record each deviation from a policy as a finding entry, for the strategic review. Change no policy here.
4. **Note.** Write the [evidence note](../kernel/processes/feedback.md#^evidence-note), one per principal where there are several.
5. **Waits.** Schedule the follow-ups that fall within the week, and apply the fallback of each wait whose latest date has passed.
6. **Checkpoints.** List the items whose appetite is consumed or will be within the week, and run a [checkpoint decision](checkpoint-decision.md) for each.
7. **Buffers.** For each deadline whose buffer is running ahead, note it: the selection rule will raise it.
8. **Commit.** Set to the state `week` the tasks that serve the milestones and the questions of the cycle, within the capacity that each stream receives.
9. **Calendar.** Confirm the themes, the windows and the committed blocks of the week, departing from the template where the availability requires it. Keep the floors at their positions.

> [!NOTE]
> Steps 5 and 7 are skipped when the corresponding option is off.
